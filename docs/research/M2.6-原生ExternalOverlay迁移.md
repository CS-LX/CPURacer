# M2.6 — 原生 External Overlay 迁移方案

**范围：** External 从 WPF layered window 迁移到原生 Win32 HWND + Direct2D；Child / SetParent 继续使用现有 WPF 路径；M3 stash 暂不恢复。

**实现状态：** M2.6.2 已通过手工验收（Topmost/前台显隐定案；托盘焦点往返不再被 Taskmgr 盖住）；External 可录屏 WGC 路径 ✅（2026-08-10）：自研会话、ExtendedFrame 裁剪、最大化贴合、无黄边、截图可见 Overlay。  
**帧时钟（2026-08-17 更新）：** External 进给已并入 App `RaceHost` 单 60Hz 循环（捕获/提取 → 物理 → `RenderNow`）。本机验收延迟更好且托盘往返无回归，**保留并钟**；承重墙仍是 Topmost + 前台显隐 + 点击穿透，而非「必须双定时器」。

## 决策

External 使用独立原生顶层窗口：

- `WS_POPUP`
- `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOPMOST | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`
- `SW_SHOWNOACTIVATE`
- 所有移动、缩放、Z 序操作带 `SWP_NOACTIVATE`
- Direct2D HWND render target 持续绘制
- External 不设置 `WDA_EXCLUDEFROMCAPTURE`，使截图 / 录屏能看到 Overlay

## Z 序（M2.6.2 实机定案）

原计划希望把 Overlay 放在 Taskmgr 主窗口正上方、同属普通 Z 序：

```text
其它前台窗口
Native External Overlay
Taskmgr
更低窗口
```

但在当前普通权限 Taskmgr 上，两种结构化相对 Z 序方案均被 Windows 拒绝：

- `SetWindowPos(overlay, externalInsertAfter, ...)` → `ERROR_ACCESS_DENIED (5)`
- `CreateWindowEx(..., hWndOwner=Taskmgr, ...)` → `ERROR_ACCESS_DENIED (5)`

因此在“不提升权限、不注入 Taskmgr”的硬边界下，不能建立跨进程相对 Z 序。
M2.6.2 使用可验证的稳定降级：

- Overlay 创建时固定 `WS_EX_TOPMOST`
- Taskmgr 或 CPURacer 托盘菜单前台：显示 Overlay
- 其它应用前台：Hide Overlay，避免 Topmost 泄漏到其它应用之上
- Overlay 保持 `WS_EX_TRANSPARENT | WS_EX_NOACTIVATE`，不参与焦点切换

这不是 WPF 时代的“失焦移到屏外”补丁，而是 UIPI 阻止跨进程相对 Z 序后的
明确产品策略；显示恢复由**持续 ticking 的帧循环**和进程级前台判定保证。

M2.6 最初沿用了 M2.5 的 `CompositionTarget.Rendering`，但迁移后的 External
是原生 HWND，不再参与 WPF 合成；同时 App 唯一的 WPF 壳窗口已隐藏。因此该事件
只会在托盘交互等场景偶发产生几帧，Taskmgr 重新获得焦点后，几何、捕获、绘制和
`HWND_TOP` 修正都可能停止。这正是“点击跟踪瞬间可见，Taskmgr 获焦后消失”的根因。

M2.6.1 改为 UI Dispatcher 上 16ms 时钟（曾为独立 `_externalTimer`；**2026-08-17** 起由
`RaceHost` 兼跑 External 进给 + `RenderNow`）：

- 原生 HWND 无论 WPF 是否重绘都持续更新；
- Taskmgr 成为前台后，下一 tick 恢复 Topmost Overlay；
- 其它应用成为前台时隐藏 Overlay。

前台判定也不能只沿 `GetParent` 查找：Win11 XAML Taskmgr 可能把实际激活面
暴露为同一进程中的另一个顶层 HWND，其父链不会到达 `TaskManagerWindow`。
Overlay 与 TrackNative 现均使用“父链命中 **或前台 HWND 与 Taskmgr 主窗同
进程**”判定，避免托盘/Alt+Tab 往返后持续误报 `cap=occluded`。

## 职责边界

| 层 | 职责 |
|---|---|
| TrackNative C++ | 发现 Taskmgr / CPU chart，过滤扫描瞬断 |
| TaskmgrWindowCapture C# | 自研 WGC 采 Taskmgr window，ExtendedFrame 屏幕坐标裁 ROI；StartCapture 前关黄边；不采独立 Overlay |
| NativeExternalOverlay C# | 原生 HWND、Z 序、逐帧几何、拟合、Direct2D 绘制 |
| WPF OverlayWindow | 仅保留 Child / SetParent |
| App | External：`RaceHost` 单环（进给+物理+RenderNow）；Child：捕获 DispatcherTimer |

## 迁移步骤

1. 增加最小 Win32 窗口封装，创建时一次性确定扩展样式。
2. 增加 Direct2D 资源：factory、HWND render target、画刷、DirectWrite 文本。
3. 将 External 的逐帧 ROI、捕获、拟合、状态迁入原生 Overlay。
4. App External 使用原生 Overlay；Child 继续使用 WPF。
5. 删除 WPF External 的焦点、点击、软隐藏、前台显隐补丁。
6. 恢复 M3 时将车体/HUD 作为原生 Overlay 的帧快照绘制。

## 验收门禁

1. 连续点击图表 100 次：Taskmgr 不失焦，Overlay 不闪藏。
2. 连续拖动 / 四边 resize：无冻结、残影、错位。
3. 浏览器覆盖 Taskmgr：浏览器自然遮住 Overlay。
4. 切回 Taskmgr：Overlay 位于图表上方。
5. 非 CPU 页 / 最小化：Overlay 隐藏。
6. WGC 地形帧不含车、红框、橙线；系统截图 / OBS 显示捕获能看到 Overlay。
7. 浅色/深色拟合线保持通过。
8. Taskmgr 最大化：橙线仍贴蓝线；捕获指示黄边关闭（需 borderless 授权）。

### M2.6.1 扩展门禁（补测焦点往返）

1. Taskmgr 前台稳定显示 Overlay。
2. 右键托盘打开菜单，**不点击任何菜单项**，再点击 Taskmgr 图表空白：Overlay 不消失。
3. 重复上一步 20 次；再分别点击红框、橙线附近，Overlay 不消失。
4. 托盘菜单打开期间允许 `cap=occluded`、拟合线暂时停在上一可靠帧；菜单关闭并点回 Taskmgr 后应在一个 tick 内恢复 `cap=ok` 和滚动。
5. 浏览器覆盖 Taskmgr：浏览器仍在 Overlay 上方；切回 Taskmgr 后 Overlay 立即回到图表上方。
