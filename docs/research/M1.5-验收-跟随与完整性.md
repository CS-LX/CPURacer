# M1.5 验收记录 — 跟随方式 × 完整性级别

**日期：** 2026-08-08  
**结论：** M1.5 **通过验收**（双跟随模式在对应完整性下可用）。下列对照为**单次实验**观察，未做系统化复现矩阵，先记债。

## 环境

- Win11（Build 26200 一带）
- Taskmgr 性能 → CPU 大图
- CPURacer：`TrackNative` + 托盘切换「外部 Overlay」/「子窗 SetParent」

## 观察矩阵（单次）

| CPURacer 启动方式 | 外部 Overlay（WinEvent） | 子窗 SetParent |
|---|---|---|
| **普通（非提升）** | 可用：能钉住 CPU 大图并跟随 | 异常：窗口停在**屏幕左上角**，未正确挂到图表 |
| **管理员（提升）** | 异常：位置乱飘，甚至贴到**内存等其它图** | 可用：TaskmgrPlayer 式跟随正常 |

> 上表「可用 / 异常」来自一次手工试跑；对侧组合未排除偶发因素（DPI、多显示器、Taskmgr 是否同级提升等）。

## 可能原因（待验证，非定论）

1. **UIPI / 完整性**：非提升进程对提升后的 Taskmgr 做 `SetParent` 常被拒绝或表现异常 → 与「普通 + 子窗失败」相符。  
2. **提升后的外部 Overlay**：屏幕坐标 / 前台判定 / sticky CPU HWND 在跨完整性或跨页时可能误绑 → 与「管理员 + 外部乱飘、贴内存」方向一致。  
3. Taskmgr 本身是否提升、与 CPURacer 是否**同级**，会影响哪条路径能通。

## 临时使用建议

- 日常验收 / 开发：优先 **普通权限 + 外部 Overlay**，或 **管理员 + 子窗 SetParent**。  
- 不要假设两种跟随在两种完整性下行为一致。
